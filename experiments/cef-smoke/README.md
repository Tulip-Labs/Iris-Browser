# CEF smoke test

The smallest proof CEF works on the Odin stack: a thin harness over the
Iris CEF engine (`linux/src/cef`, slice 1 of the CEF Flatpak plan) that
inits CEF (no sandbox, windowless off-screen rendering, external message
pump), runs two scenarios, and prints `PASS` only if both pass. Anything
else prints `FAIL` and exits 1.

- **Scenario 1 — tab close frees memory.** Opens 3 tabs on distinct pages,
  records the CEF process tree and its total RSS, closes 2 tabs, and
  requires the closed tabs' memory to be really gone: fewer CEF processes
  and total RSS at most 70% of before. This is the guarantee the WPE
  WebKit build lacked in 2.2.0–2.2.2 (a closed tab's page lived on, video
  kept playing, memory never came back, because Iris held one reference
  too many on each page).
- **Scenario 2 — single page frame.** Opens https://example.org, waits for
  one `OnPaint` frame, dumps it to `frame.ppm`.

This is an experiment, not Iris: nothing in `android/` or `packaging/` is
touched, and the WPE build is the default. See `cef-linux-retry-
INVESTIGATION.md` at the repo root for why this exists and what the full
swap would cost, and `cef-linux-flatpak-PLAN.md` for the slices — this
harness is slice 1's proof, the engine is the slice 1 deliverable.

Pinned versions: **CEF 156.0.32** (Chromium 156.0.8078.109, minimal
distribution) and **Odin dev-2026-11a** (the same Odin `linux.yml` pins).

## Run it locally

```sh
# once: fetch the CEF minimal tarball (318 MB) and unpack it
curl -sSfL "https://cef-builds.spotifycdn.com/cef_binary_156.0.32+g3d1f4ab+chromium-156.0.8078.109_linux64_minimal.tar.bz2" -o cef.tar.bz2
tar -xjf cef.tar.bz2

export CEF_DIR=$PWD/cef_binary_156.0.32+g3d1f4ab+chromium-156.0.8078.109_linux64_minimal
# CEF resolves the ICU data file from the libcef.so directory, not from
# resources_dir_path: the resource files must sit next to libcef.so, or
# CefInitialize dies with "Invalid file descriptor to ICU data received".
cp "$CEF_DIR/Resources/icudtl.dat" "$CEF_DIR/Resources/"*.pak "$CEF_DIR/Release/"
./build.sh   # builds ./cef-smoke (needs odin + clang on PATH, or ODIN=path)
./run.sh     # PASS: tab close frees memory ... / PASS: single page frame 800x600 -> frame.ppm
```

The tarball and the extracted tree are gitignored; they are never committed.
`frame.ppm` is a P6 RGB dump of the settled frame (the program waits until
the page has loaded and no new paint has arrived for a second, so the first
partial paint is not what gets dumped).

## Files

- `main.odin` — the harness: the two scenarios, over the engine's API
  (`cef.new_browser`, `cef.wait_created`, `cef.close_browser`,
  `cef.pump`, per-tab `on_frame` / `on_loading` / `on_close`
  callbacks). It holds no CEF handler of its own.
- `linux/src/cef/` — the engine: `cef.odin` (the CEF C API structs,
  hand-written from the headers, each marked for
  `linux/abi/check.py`), `cef_gen.odin` (the foreign functions,
  generated by `tools/bind.py` from `cef.txt`; regenerate with
  `sh gen.sh` in that directory, needs `CEF_DIR` + clang),
  `engine.odin` (the `Browser` type and the whole engine),
  `engine_test.odin` (pure unit tests), `README.md` (the engine's own
  doc, including the tab-close rules and the ownership rules).
- `build.sh`, `run.sh` — build / run.
- `.github/workflows/cef-smoke.yml` — CI: downloads CEF, regenerates the
  bindings and diffs them, runs the ABI check, runs the engine's unit
  tests, builds, runs, uploads the frame as an artifact.

## What it proves (and does not)

Proves: the CEF download, the Odin bindings, the subprocess spawn, the
paint path, and the tab-close memory guarantee — the five things the full
engine swap depends on. It does not prove Shields, input, video, or the
Flatpak sandbox story; those are the next steps if this passes.

## Tab close: the process-model findings (2026-11-24)

Verified against CEF 156 / Chromium 156 headers and `libcef.so` strings,
and by the running program. These are the rules Iris must follow so a
closed tab really dies:

1. **A separate `CefRequestContext` per tab is the mechanism that forces
   a separate renderer process per tab.** CEF's default is to share one
   renderer process across same-site browsers, so closing one tab would
   not drop memory until every tab in that process closed. Distinct
   storage partitions cannot share a renderer, so a fresh context per tab
   (`cef_request_context_create_context`, empty `cache_path` = in-memory
   partition) isolates them. Cost to carry into Iris: separate contexts
   mean separate cookies/storage per tab — shared login state across tabs
   breaks unless Iris uses shared contexts or accepts same-site renderer
   sharing. The smoke test creates each tab with its own context.
2. **There is no `--process-per-tab` switch in CEF 156.** Zero matches
   in `libcef.so` strings (while `process-per-site`, `site-per-process`
   and `renderer-process-limit` do exist). The switch cannot be the
   mechanism; the per-tab request context is.
3. **`CefBrowserHost::CloseBrowser(force_close=1)` destroys the tab.**
   `DoClose` returning 0 destroys the browser immediately in windowless
   mode; `OnBeforeClose` is the signal the browser object is being
   destroyed — that is where Iris must drop every reference to the tab
   (`CefBrowser`, `CefBrowserHost`, client, any map entry). Any reference
   kept past `OnBeforeClose` keeps the page and its renderer alive: the
   WPE bug, in CEF form.
4. **Match tabs by browser identifier, not by pointer.** CEF hands
   `OnBeforeClose` a *different* `cef_browser_t*` wrapper than
   `OnAfterCreated` did for the same tab, so pointer equality never
   matches and the reference is never dropped. `get_identifier()` is
   stable across the callbacks; the smoke test stores the id at creation
   and matches on it at close. (This exact bug cost a full debug round:
   `do_close` and `on_before_close` fired, but `tabs_closed` stayed 0.)
5. **You cannot count renderers by `--type=renderer`.** Chromium spawns
   subprocesses by forking the zygote, and the forked child never execs,
   so its `/proc/PID/cmdline` keeps the zygote's text (`--type=zygote`)
   even after it becomes a renderer or the GPU process. Verified:
   6 descendants, all named `cef-smoke` with `--type=zygote` cmdlines,
   the 4 grandchildren holding the pages at ~45–122 MB RSS each. The
   smoke test therefore measures the **whole CEF subtree** (every
   descendant process, summed VmRSS): when tabs really die, their
   processes leave the tree and the total falls. A leak would show up as
   processes that never leave.

Measured locally (2026-11-24, two consecutive runs, three small example
pages): before close 8 CEF processes / ~774,000 kB RSS; after closing 2
of 3 tabs 6 processes / ~511,000–523,000 kB (66–68% of before). Re-run
through the engine (2026-11-25, three consecutive runs): 8 → 6
processes, RSS 773,860 → 511,788 kB (66.1%), 778,680 → 519,492 kB
(66.7%), 777,204 → 519,944 kB (66.9%). The PASS threshold is RSS at
most 70% of before *and* a strictly smaller process count. The 70% line
is deliberate: a leak leaves RSS near 100% (the dead weight is the two
renderers, ~250 MB of ~774 MB here), while normal run-to-run variance on
these small pages is ~12 MB.

## Gotchas found while making it pass (2026-11-24)

- **`cef_api_hash` first.** Since CEF 133 the C API requires
  `cef_api_hash(CEF_API_VERSION, 0)` before any other CEF call, in *every*
  process (the subprocesses re-enter `main`, so the call at the top of
  `main` covers them). Without it the CToCpp wrappers die with
  `CefClient_0_CToCpp called with invalid version -1`.
- **ICU data lives next to libcef.so.** `resources_dir_path` is honoured
  for the resource bundle, but the ICU data file is resolved from the
  libcef.so directory (`DIR_ASSETS`). Copy `Resources/icudtl.dat` and
  `Resources/*.pak` into `Release/` (the workflow does this too).
- **No X server, no paints.** With no `$DISPLAY` the program appends
  `--headless=new --ozone-platform=headless`, and SwiftShader GL
  (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`):
  without a working GL the GPU/viz process cannot initialise and the
  compositor never produces a frame (paints stay at 0 even though the
  page loads with HTTP 200). Behind a MITM proxy it also appends
  `--ignore-certificate-errors` — CEF 156 has no
  `ignore_certificate_errors` settings field any more; the switch is the
  way. All of this only applies when `$DISPLAY` is unset; on a machine
  with X the program runs unmodified.
- **Odin needs `clang` as its linker driver.** If `clang` disappears from
  the machine (a VM replacement wipes `/usr` installs), every `odin
  build` fails with `Could not spawn subprocess: No such file or
  directory`. Reinstall it (`apt-get install -y clang`); `cc`/`gcc` being
  present does not help.
- **`os.args` is a slice, not `[dynamic]`.** `append` cannot grow it;
  copy it into a `[dynamic]string` first.
- **`"c"` callbacks have no implicit `context`.** Each callback that
  calls `fmt`/`make`/`os` must start with
  `context = runtime.default_context()` (`base:runtime` in this Odin).
- **ABI check invocation.** `check.py --import` needs an *absolute*
  path (`--import main=$PWD`); `.` makes the collection path empty and
  the probe fails with `Expected 'name=path', got 'chk0='`.
- **Renderer processes are grandchildren, not children.** The browser
  process spawns a zygote, and the zygote forks the renderers — walk
  `/proc/<pid>/task/<pid>/children` recursively, not just one level.
  (And as noted above, the forked children keep `--type=zygote` in their
  cmdline, so identify the subtree by ancestry, not by type flag.)
- **`tar` as root needs `--no-same-owner`**, for both the Odin and the
  CEF tarballs.

## Gotchas found while building the engine (slice 1, 2026-11-25)

- **A `defer` inside an `if` block runs when the block ends, not when
  the function ends.** `init` once freed the `root_cache_path` /
  `resources_dir_path` / `locales_dir_path` strings with a `defer`
  inside each `if` — CEF then initialised with empty paths (the
  `root_cache_path` warning gave it away) and trapped inside
  `CefInitialize`. The engine frees those strings explicitly after
  `cef_initialize` returns.
- **`time.diff(a, b)` is `b - a`.** `wait_created` and the harness's
  deadline checks once used `time.diff(time.now(), deadline) > 0`,
  which is true from the first check (deadline − now is positive), so
  every wait returned instantly. Deadlines use `time.since(deadline) >=
  0` now.
- **A refcounted object passed to a CEF function belongs to CEF
  afterwards.** Releasing the tab's request context in `OnBeforeClose`
  segfaulted: `CefBrowserHostCreateBrowser` takes ownership of the
  context, and CEF frees it as the tab dies. The engine releases only
  what CEF *returns* to it (the host from `get_host`) and never what it
  *passed in*. The rule is written in `engine.odin`'s header comment.
  (The old harness never released anything, which is why it never hit
  this.)
- **Printing a `Browser` prints its frame.** A debug `eprintln` of the
  whole struct dumped the 800×600×4 BGRA buffer as numbers (~9.5 MB
  of log). Print the id and the URL, never the struct.
